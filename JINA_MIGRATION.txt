JINA -> DIRECT API MIGRATION — DECISION
Updated 2026-07-08 after live endpoint re-probing.
Priority: DURABILITY. Migrate only where a direct API is durable AND reachable.

================================================================================
DECISION: MIGRATE NETAPP ONLY. KEEP EVERYTHING ELSE ON JINA (top up credits).

Rationale
  Only NetApp offers a direct API that is BOTH durable and reachable today.
  Every other custom site is either an HTML scrape (breaks silently on
  redesign) or a gated API (unreachable) — for those, Jina is the MORE durable
  choice, because it extracts rendered content semantically rather than parsing
  brittle markup, and it fails loudly (empty/error) rather than silently.

  Google, Apple, Tesla, IBM, Fidelity, SAS, Rivian, Lenovo, Cisco.

  Why each stays:
    Google / Apple / IBM / Fidelity / Tesla : gated or JS-only. Direct APIs are
        removed, CSRF-gated, or bot-blocked. Jina renders past this.
    SAS / Rivian : iCIMS iframe shell returns HTML, not JSON. Rivian did NOT

    Cisco : Phenom API reachable but returns "Tenant not identified" on every
        domain value tried; needs an unresolved tenant/CSRF handshake.
        Durable IF unlocked, but blocked today — nothing to migrate.
